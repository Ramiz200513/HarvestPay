# Harvest Pay

BNPL-маркетплейс семян и удобрений для фермеров Казахстана. Кредитоспособность хозяйства оценивается не по залогу,
а по истории поля со спутника: 7 сезонов NDVI (Sentinel-2) + влажность почвы (Sentinel-1) + климат района (ERA5-Land)
+ проверка юрлица по БИН (реестр, налоги, аресты, суды). Поставщик получает деньги сразу со скидкой, фермер платит
после уборки, деньги на весну — кредитная линия банка. Схема денег и рисков — в [docs/finance-scheme.md](docs/finance-scheme.md).

Команда: Галиакберов Рамиз (тимлид, бэкенд) · Болатканов Бекжан (фронтенд, UX/UI) · Попов Евгений (ГИС) ·
Орешин Владислав (скоринг, QA).

| Для кого | Что есть |

```
│   │   ├── worker.py            Celery-воркер
│   │   ├── seed.py              стартовый каталог товаров
│   │   ├── migrate.py           применение миграций при старте API

│   │       ├── overlap.py       антифрод: пересечения с чужими полями (PostGIS / shapely)
│   │       ├── satellite/       mock.py (демо) и gee.py (Google Earth Engine)
│   │       ├── scoring.py       индекс стабильности и класс A/B/C (+ климатический штраф)

│   │       ├── limits.py        лимит и график платежей
│   │       ├── finance.py       экономика сделки, кредитная линия, шаги сделки, сценарий неурожая
│   │       ├── monitoring.py    спутниковый мониторинг сезона: сев и отставание от нормы
│   │       └── pipeline.py      весь конвейер обработки заявки
│   ├── migrations/versions/     миграции: 0001 — начальная, 0002 — PostGIS, 0003 — поставщики и сделки
│   ├── alembic.ini              настройки Alembic
│   └── tests/                   pytest: test_domain.py, test_marketplace.py (логика), test_api.py (HTTP)
├── frontend/                    React 18 + TypeScript + Vite + Leaflet
│   └── src/
│       ├── pages/               Landing, Apply (мастер), ApplicationPage, Analyst
│       ├── components/          FieldMap, NdviChart, ApplicationDetails, DealPanel, MonitoringChart, PortfolioView
│       ├── lib/                 geo.ts (площадь), kml.ts (импорт границ), format.ts, storage.ts
│       ├── api.ts               клиент к API
│       └── types.ts             типы, повторяющие схемы бэкенда
├── docker-compose.yml           PostgreSQL+PostGIS, Redis, API, воркер, сайт
└── .env.example                 все настройки с пояснениями
```

Почему `services/` отдельно от `api/`: вся логика (скоринг, БИН, геометрия) — обычные функции без FastAPI и БД.
Их можно тестировать за миллисекунды, а API — только «склейка»: принять запрос → вызвать сервис → сохранить → ответить.

## Запуск без Docker (проще всего для разработки)

Нужны Python 3.11+ и Node.js 18+.

**1. Бэкенд** (в первом терминале):

```powershell
cd backend
python -m venv .venv
.venv\Scripts\activate          # Windows PowerShell;  на macOS/Linux: source .venv/bin/activate
pip install -r requirements-dev.txt
uvicorn app.main:app --reload
```

API поднимется на http://localhost:8000, документация Swagger — http://localhost:8000/docs.
База — файл `backend/harvestpay.db` (SQLite), создаётся сама: при старте API применяет миграции. Расчёт идёт в фоне
внутри процесса API — Redis не нужен. Пересечения полей в режиме SQLite считает библиотека shapely, без PostGIS.

**2. Фронтенд** (во втором терминале):

```powershell
cd frontend
npm install
npm run dev
```

Сайт откроется на http://localhost:5173. Запросы `/api/*` Vite сам перенаправляет на бэкенд.

**3. Тесты:**

```powershell
cd backend
pytest                      # 39 тестов на временной SQLite-базе
```

Те же тесты на PostgreSQL + PostGIS (например, на базе из `docker compose up db`):

```powershell
$env:HP_TEST_DATABASE_URL = "postgresql+psycopg://harvestpay:harvestpay@localhost:5432/harvestpay_test"
pytest
```

Схема `public` в этой базе очищается перед прогоном — не указывайте рабочую БД.

**Миграции схемы БД.** API применяет их сам при старте. Если поменяли `models.py`:

```powershell
cd backend
alembic revision --autogenerate -m "что изменили"   # создаст файл в migrations/versions — проверьте его глазами
alembic upgrade head                                 # применить
```

## Запуск через Docker (как в продакшене)

Нужен только [Docker Desktop](https://www.docker.com/products/docker-desktop/). На Windows — скрипт `hp.cmd`
в корне проекта (сам запустит Docker Desktop, создаст `.env` из `.env.example`, соберёт образы и дождётся API):

```powershell
.\hp.cmd              # поднять всё в фоне (то же, что .\hp.cmd up)
.\hp.cmd logs         # логи всех сервисов; .\hp.cmd logs api — одного
.\hp.cmd ps           # состояние контейнеров
.\hp.cmd down         # остановить (база сохраняется)
.\hp.cmd reset        # остановить и удалить базу со всеми заявками
```

На macOS/Linux или вручную — то же самое через compose:

```bash
cp .env.example .env
docker compose up --build -d
```

- Сайт: http://localhost:8080
- API: http://localhost:8000/docs

Здесь уже настоящая архитектура из проекта: PostgreSQL с PostGIS, очередь Redis и отдельный Celery-воркер.
После правки кода достаточно снова выполнить `.\hp.cmd` — пересоберутся только изменённые образы.

## Демо-сценарий для защиты

1. Откройте «Подать заявку», нажмите демо-БИН `150343000016` (КХ «Нур Егін», проходит проверку).
   Для показа отказа — `080740000019` (ликвидировано) или `260440000016` (зарегистрировано недавно).
2. Обведите поле кликами по снимку (3+ точки). Площадь считается сразу.
3. Добавьте семена/удобрения, отправьте. Через пару секунд — класс, лимит, график платежей и график NDVI.
4. Разные поля получают разные «истории»: попробуйте несколько участков — встретятся классы A, B и C.
5. Заявка класса C появится в «Аналитику» (токен `analyst-demo-token`) — одобрите её вручную.
6. **Антифрод:** подайте вторую заявку с БИН `180240000011` и обведите то же поле. Уже на шаге «Поле» появится
   предупреждение, а заявка уйдёт аналитику с меткой «пересечение» — у него чужое поле видно красным пунктиром.
7. **Проверка юрлица:** `170343000014` — отказ из-за налогового долга, `160540000019` — арест счетов,
   `250643000018` (хозяйству 1 год) и `190340000017` (есть суд) проходят, но получают не выше класса B.
8. **Деньги:** у аналитика вкладка «Портфель и деньги» — кредитная линия, ожидаемые поступления, доход по сделкам.
   Откройте одобренную сделку: экономика, движение денег по шагам и таблица «если случится неурожай».
   Проведите сделку по шагам: «Банк оплатил поставщикам» → «Товар отгружен» → «Проверить поле» (спутниковый
   мониторинг) → внесите платёж фермера или перенесите остаток на следующий сезон.

В демо-режиме данные спутника синтетические, но детерминированные: одно и то же поле всегда получает одинаковый
результат. На сайте об этом честно написано плашкой.

## Как считается решение

```
БИН ──► формат + контрольная цифра ──► реестр (существует? действует? старше 12 мес.?)
                                             │ нет → отказ
                                             ▼ да
    + налоги (долг > 100 000 ₸ → отказ), аресты (→ отказ), суды (→ не выше B)

Контур поля ──► проверка полигона, площадь ──► антифрод ──► очередь ──► спутник: 7 сезонов + климат
                                                              │
         ┌────────────────────────────────────────────────────┘
         ▼
  индекс стабильности = 0.5·уровень NDVI + 0.3·(100 − разброс) + 0.2·тренд
                        − 5 при сухой почве − до 8 за заморозки и жару в районе
         │
         ├─ ≥ 75  → класс A → лимит 100% (площадь × 60 000 ₸/га, но ≤ 20 млн) → одобрено автоматически
         ├─ 50–74 → класс B → лимит 60% (≤ 10 млн)                          → одобрено автоматически
         └─ < 50  → класс C → аналитик решает вручную
         │
  андеррайтинг: класс A только хозяйствам старше 2 лет и без судов, иначе B
  кредитная линия: если в ней не хватает денег на оплату поставщикам — решение за аналитиком
         │
  одобрено → открывается сделка: резерв в линии, оплата поставщику 1 апреля, платежи фермера 15.10 и 15.11
```

Одобренная сумма = min(запрошено, лимит). Оплата двумя платежами — 15 октября и 15 ноября (после уборки),
комиссия за сезон: A — 6%, B — 10%, C — 14%. Все коэффициенты — в `services/scoring.py` и `services/limits.py`.

Почему скоркарта, а не нейросеть: истории дефолтов казахстанских хозяйств нет, обучать модель не на чем.
Скоркарта прозрачна — каждый балл объясняется фермеру на странице заявки.

## Подключение Google Earth Engine (реальные снимки)

1. Создайте проект в Google Cloud Console, включите **Earth Engine API**.
2. Зарегистрируйте проект для некоммерческого/учебного использования: https://code.earthengine.google.com/register
3. Создайте сервисный аккаунт (IAM → Service Accounts), выдайте роли
   **Earth Engine Resource Viewer** и **Service Usage Consumer**, скачайте JSON-ключ.
4. Положите ключ в `secrets/gee-key.json` и задайте в `.env`:
   ```
   HP_SATELLITE_PROVIDER=gee
   HP_GEE_PROJECT=<id проекта>
   HP_GEE_SERVICE_ACCOUNT=<email сервисного аккаунта>
   HP_GEE_KEY_FILE=/secrets/gee-key.json     # без Docker — полный путь к файлу
   ```
5. Для расчёта через GEE лучше режим `HP_TASK_MODE=celery`: один запрос идёт 10–60 секунд.

Что считается: Sentinel-2 L2A, маска облаков по слою SCL (только «растительность» и «почва»),
NDVI = (B8 − B4)/(B8 + B4), 90-й перцентиль за апрель–сентябрь; влажность — радар Sentinel-1 (VV), апрель–июнь.
Все 7 сезонов запрашиваются одним `getInfo()`. Результаты кэшируются в таблице `field_seasons` — повторная заявка
по тому же полю к спутнику не ходит.

> Важно: код GEE-провайдера написан, но в демо-окружении разработки не проверялся на реальном аккаунте —
> первый запуск с ключом стоит сделать заранее, до защиты.

## API

| Метод | Путь | Что делает |
|---|---|---|
| POST | `/api/farms/verify` | проверка хозяйства по БИН |
| GET | `/api/products` | каталог товаров |
| POST | `/api/fields/check` | проверить контур: площадь и пересечения с чужими полями |
| POST | `/api/applications` | подать заявку (БИН + GeoJSON поля + товары) |
| GET | `/api/applications/{id}` | статус, решение, сезоны NDVI |
| GET | `/api/analyst/applications?status=review` | очередь аналитика (заголовок `X-Analyst-Token`) |
| POST | `/api/analyst/applications/{id}/decision` | одобрить / отказать вручную |
| POST | `/api/analyst/applications/{id}/retry` | перезапуск после ошибки |
| GET | `/api/analyst/portfolio` | портфель сделок и кредитная линия |
| POST | `/api/analyst/deals/{id}/action` | шаг сделки: `pay_supplier`, `confirm_delivery`, `confirm_sowing`, `record_payment`, `restructure` |
| POST | `/api/analyst/deals/{id}/monitoring` | спутниковый мониторинг сезона по полю сделки |
| GET | `/api/config` | какие источники данных включены |

Подробно, с примерами и кнопкой «Try it out» — на http://localhost:8000/docs.
