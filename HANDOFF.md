## 1. Что это за проект

**Harvest Pay** — учебный проект по предмету «ИТ-продукт». B2B-рассрочка (BNPL) на семена и удобрения
для фермеров Казахстана. Идея: кредитоспособность хозяйства оценивается не по залогу техники,
а по истории поля со спутника — 7 сезонов NDVI (Sentinel-2) + влажность почвы (Sentinel-1) +
проверка юрлица по БИН.

**Команда (4 человека):** Галиакберов Рамиз (тимлид, бэкенд) · Болатканов Бекжан (фронтенд, UX/UI) ·
Попов Евгений (ГИС) · Орешин Владислав (скоринг, QA).

Проект сдаётся с устной защитой. Материалы к защите — в разделе 7.

## 4. Как запустить

### Без Docker (для разработки)

Нужны Python 3.11+ и Node.js 18+. Два окна PowerShell.

Окно 1 — бэкенд:
```powershell
cd $HOME\PycharmProjects\HarvestPay\backend
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements-dev.txt
uvicorn app.main:app --reload
```
API: http://localhost:8000 · Swagger: http://localhost:8000/docs

Окно 2 — сайт:
```powershell
cd $HOME\PycharmProjects\HarvestPay\frontend
npm install
npm run dev
```
Сайт: http://localhost:5173

База — файл `backend/harvestpay.db` (SQLite), создаётся сама: при старте API применяет миграции.
Redis не нужен, расчёт идёт в фоне внутри процесса API.

### Через Docker (полная архитектура)

```powershell
docker compose up --build
```
Сайт: http://localhost:8080 · API: http://localhost:8000/docs
Поднимаются PostgreSQL+PostGIS, Redis, API, Celery-воркер и nginx с собранным сайтом.

### Тесты

```powershell
cd backend
pytest                                   # 39 тестов на временной SQLite-базе
```

На PostgreSQL+PostGIS (схема `public` указанной базы очищается перед прогоном!):
```powershell
$env:HP_TEST_DATABASE_URL = "postgresql+psycopg://harvestpay:harvestpay@localhost:5432/harvestpay_test"
pytest
```

### Демо-сценарий (его же показывать на защите)

1. «Подать заявку» → демо-БИН `150343000016` (КХ «Нур Егін», проходит проверку).
   Отказы: `080740000019` (ликвидировано), `260440000016` (зарегистрировано недавно).
2. Обвести поле кликами по снимку (3+ точки), выбрать товары, отправить.
3. Через пару секунд — класс риска, лимит, график платежей, график NDVI по сезонам.
4. Разные поля дают разные «истории» — встречаются классы A, B и C.
5. Заявка класса C → «Аналитику», токен `analyst-demo-token`, одобрить вручную.

**Путь заявки:**
```
БИН ──► формат + контрольная цифра ──► реестр (существует? действует? старше 12 мес.?)
                                             │ нет → отказ
                                             ▼ да
Контур поля ──► проверка полигона, площадь ──► антифрод: пересечения с чужими полями
                                             ──► очередь ──► спутник: 7 сезонов NDVI
         ┌───────────────────────────────────────────────────┘
         ▼
  индекс стабильности = 0.5·уровень NDVI + 0.3·(100 − разброс) + 0.2·тренд   (−5 при сухой почве)
         │
         ├─ ≥ 75  → класс A → лимит 100% (площадь × 60 000 ₸/га) → одобрено автоматически
         ├─ 50–74 → класс B → лимит 60%                         → одобрено автоматически
         └─ < 50  → класс C → аналитик решает вручную
```
Если найдено пересечение с чужим полем ≥ 10% — заявка в любом случае уходит аналитику,
сумма 0 до проверки документов на землю.

**API:**

| Метод | Путь | Что делает |
|---|---|---|
| POST | `/api/farms/verify` | проверка хозяйства по БИН |
| GET | `/api/products` | каталог товаров |
| POST | `/api/fields/check` | проверить контур: площадь и пересечения (живая проверка в мастере) |
| POST | `/api/applications` | подать заявку |
| GET | `/api/applications/{id}` | статус, решение, сезоны NDVI |
| GET | `/api/analyst/applications?status=review` | очередь аналитика (заголовок `X-Analyst-Token`) |
| POST | `/api/analyst/applications/{id}/decision` | одобрить / отказать вручную |
| POST | `/api/analyst/applications/{id}/retry` | перезапуск после ошибки |
| GET | `/api/config` | какие источники данных включены |

## 6. Принятые решения и почему (это спрашивают на защите)

- **Скоркарта, а не нейросеть.** Истории дефолтов казахстанских хозяйств не существует — обучать
  модель не на чем. Скоркарта прозрачна: каждый балл объясняется фермеру прямо на странице заявки.
  Называть набор правил «искусственным интеллектом» было бы нечестно перед комиссией.
- **Python + FastAPI** — у Google Earth Engine нативный Python API, не нужен мост к другому языку.
- **PostGIS** — пространственные запросы над геометрией поля (пересечения) и GIST-индекс вместо
  перебора всех полей подряд.
- **Celery + Redis** — запрос к спутнику идёт 10–60 секунд и не имеет права блокировать интерфейс.
  Для разработки есть режим `HP_TASK_MODE=background` без Redis.
- **React + Leaflet** — основной сценарий фермера это рисование полигона поля рукой на карте.
- **`services/` отдельно от `api/`** — логика это обычные функции без фреймворка, тестируются за
  миллисекунды; API только «склейка»: принять запрос → вызвать сервис → сохранить → ответить.
- **Маска облаков обязательна** (слой SCL у Sentinel-2): без неё облако даёт ложный провал NDVI,
  и честное хозяйство получило бы плохой балл.
- **Два провайдера у каждого внешнего источника** (демо и настоящий) — проект показывается и
  разрабатывается без ключей и интернета, переключение одной переменной окружения.
- **Пересечение < 10% игнорируется** — соседи рисуют общую границу кликами, контуры неизбежно
  немного залезают друг на друга.
- **Фермер не видит, чьё поле пересекается** — только площадь и долю; владельца и контур видит
  лишь аналитик.
